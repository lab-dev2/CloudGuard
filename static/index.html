Key Takeaways for Cloud Architects:

  • Defense-in-Depth Matters: The breach was not caused by a single bug. It required an SSRF flaw, unauthenticated IMDSv1, an overly permissive IAM role, and unconstrained S3 bucket policies simultaneously.
  • Migrate to IMDSv2: AWS IMDSv2 completely neutralizes simple SSRF attacks against instance metadata by requiring session-oriented PUT handshakes.
  • Enforce Least Privilege: Web-facing reverse proxies should never have permissions to read corporate customer databases or S3 data lakes.
  • Perimeter Isolation: S3 buckets containing sensitive financial data should require VPC Endpoints (aws:sourceVpce) and Customer Managed Keys (CMKs) with independent access controls.
